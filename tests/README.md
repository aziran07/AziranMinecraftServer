# 테스트 유지 기준

저장소 루트에서 실행한다.

```sh
python3 -m unittest discover -s tests -v
node --test tests/test_join_guide_copy.cjs
```

전체 Python 검사는 설치된 서버 JAR, `client-mods-cache/`, 현재 버전의 `dist/` 산출물과
Docker Compose CLI가 필요하다. 파일이 없으면 실패하며 자동으로 다운로드하거나 재빌드하지 않는다.
백업 검사는 임시 월드와 가짜 Docker 명령으로 실행하고, 운영 서버의 저장 상태는 바꾸지 않는다.

## 유지할 검증

- 백업 성공·실패 시 저장 복구와 보존, Chunky의 접속자 차단·재개·오류 처리.
- 서버 JAR의 lock 일치, 중복·불필요한 JAR 및 클라이언트 전용 모드의 서버 설치 방지.
- Curios 착용을 활성화할 때 고정된 서버 전용 저장 패치가 설치돼 있는지 검사. 게임 내 저장 검증은
  [배낭 검증 절차](../docs/BACKPACK_PERSISTENCE.md)를 별도로 따른다. 클라이언트 1.1.12는
  사용자 요청에 따라 같은 패치를 포함하며, 세 배포 형식에 들어간 JAR의 해시를 검사한다.
- 클라이언트 세 배포 형식의 무결성·의존성·재배포 제한과 올바른 런처 설정.
- 재실행 크래시를 막는 단축키 기본값, 리소스팩 우선순위와 Nemo/Mouse Tweaks 충돌 방지.
- 번역 키 누락·중복, 자리표시자·링크·수량 보존, 잘못된 입력의 빌드 거부.
- 지도 프록시의 포트 노출·TLS 설정, 주소 복사의 성공·실패 표시.
- 안내 페이지 간 로컬 링크·앵커·자산 경로와 HTML ID 중복 검사.

## Curios 배낭 실제 서버 회귀 검사

```sh
python3 compat/backpack-curios/build.py
python3 tests/backpack-runtime/run.py --patch dist/backpack-curios/aziran-backpack-curios-1.0.0.jar --full-modset
```

Java 25 Docker 이미지와 설치된 서버 라이브러리·JAR이 필요하다. 운영 월드·설정은
마운트하지 않고, 별도 임시 월드와 테스트 전용 모드를 실행한다. 16개 저장·화면·
동기화·다른 착용 방식 검증 후 별도 JVM에서 파일로 저장한 Curios 데이터를 다시
읽는다. 결과 JSON과 로그는 출력된 `/tmp/aziran-backpack-test-*`에 남는다.
패치 인자를 빼면 원본 버그를 재현하므로 실패 종료가 예상된다. 실제 클라이언트
렌더링·클릭·접속, 사망/무덤 처리는 이 검사로 검증하지 않는다.

테스트 전용 JAR은 자동으로 서버를 종료한다. 운영 서버에 설치하지 않는다.
운영 패치 빌드는 `compat/backpack-curios/src/main`만 포함하고 배포 설정 검사도
테스트 클래스가 들어가지 않았는지 확인한다.

1.1.12 패키징 작업에서는 사용자 지시에 따라 위 실제 서버 검사를 추가 실행하지
않았다. 파일·아카이브 검사 통과와 싱글플레이 실행 검증을 구분한다.

## 2026-09-25 정리

기존 Python 71개와 JavaScript 2개가 모두 통과하는 상태에서 정리했다.
모드 추가마다 별도 파일에 버전·해시·배포 여부를 중복 고정하던 검사를
`test_server_mods.py`와 기존 클라이언트 전체 아카이브 검사로 통합했다.
서버 릴리스의 버전·해시는 lock을 기준으로 검증하며, 올바른 버전 선택 자체는 모드 업데이트 리뷰에서 확인한다.

Python 기본 HTTP 서버로 정적 파일의 200 응답만 확인하던 검사는 제거했다.
실제 공개 사이트 응답·화면은 배포 검증에서 확인한다([안내](../docs/JOIN_GUIDE.md#검증)).
특정 번역 문구 및 Markdown 용어집 표 구조에 결합된 검사는 제거하고,
용어 선택은 [용어집](../docs/OCCULTISM_KO_GLOSSARY.md)을 기준으로 리뷰한다.
새 모드나 문구를 추가했다는 이유만으로 동일한 일회성 검사를 늘리지 않는다.
